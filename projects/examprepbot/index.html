The course material is the boundary

A useful exam answer needs the definitions and scope taught in the course. A general-purpose model can give a plausible answer from a different textbook, mix in untaught topics, or leave a student with no way to verify a claim.

I built ExamPrepBot around that constraint: preserve the page references during ingestion, retrieve only within the selected weeks, and ask the model to cite its sources. The web app puts the cited slide beside the question, so students can inspect the evidence themselves.

    Engineering decisions behind the app

    Slides and tutorials need different treatment

    Slide pages preserve citation boundaries; tutorial chunks preserve individual questions. Removing incremental slide builds reduces repeated content. A model-and-text hash cache avoids embedding unchanged chunks again.

    Retrieval should respect the syllabus

    The default retrieval budget is four slide chunks and two tutorial chunks. Separate quotas keep long tutorials from dominating, while adjacent pages recover explanations split across slides.

    A citation check has a specific job

    The validator checks allowed labels, missing citations and a trailing block of uncited text. Failed checks trigger a rewrite. It is a structural guardrail, so source inspection remains part of the study workflow.

    Question quality needs more than a prompt

    Types and marks come from configuration. Generation oversamples source bundles, filters questions that refer vaguely to slides, checks answer/source overlap and deduplicates candidates using embeddings.

    Serving is separate from generation

    The FastAPI web server imports exported question sets on startup. The web-only Docker setup supports browsing and slide viewing without a GPU; the GPU setup adds embedding and vLLM services.

    Make failures visible

    Prometheus metrics cover citation checks, generation queues, rejected questions, ingestion and cache hits. JSONL answer logs include time to first token, total latency, token usage, retry attempts and a configuration hash.

    Current scope and next steps

    Implemented

    PDF uploads and ingestion, week-scoped retrieval, cited answer generation, question filtering, a weekly question browser, a slide viewer, seed import/export, metrics and Docker. Tests use generated PDFs and fake model implementations so they can run without a GPU.

    Still to build

    Feedback on student-written answers, OCR for image-only pages, evaluation suites and version comparisons, and extra generation when too few questions pass validation. Authentication and file deletion are also planned.
